# 新项目开工：提示词 + 开工前清单

## 一、直接粘贴给 DSH 的提示词

在**新工作区**开一个会话，把下面这段整段粘进输入框。<尖括号>里的内容按你的项目改，其余不用动。

```
这是一个新项目，工作区目录：<E:\DSH\示例项目>。
项目类型：<一句话描述，例：纯前端网页，HTML/CSS/JS，无构建工具>。

请按顺序执行，每完成一步向我汇报你做了什么、看到了什么，不要跳步：

1. 环境体检：报出 git / node / pnpm / python 的版本；缺什么先只报告，不要自行安装。
2. 初始化仓库：git init -b main。
3. 配置项目级身份（只对本仓库生效，别动全局）：
   git config --local user.name "<你的名字>"
   git config --local user.email "<你的邮箱>"
4. 生成 .gitignore，必须覆盖：依赖目录、构建产物、环境变量文件、日志、编辑器配置、证书私钥、系统杂项。
5. 生成 README.md 骨架：项目是做什么的、怎么运行、目录结构说明、后续计划。
6. 生成 .env.example，只列变量名和说明，不写真实值。
7. 生成 AGENTS.md：写清技术栈、代码风格、目录约定、禁止事项，供以后每次会话快速对齐。
8. 提交前先把 git status 的完整清单发给我，确认没有 .env、node_modules、密钥文件混进来。
9. 我确认后提交第一个 commit：chore: 初始化项目骨架。
10. 到此为止，不要推送。等我建好 GitHub 空仓库，再继续添加远程和首推。
```

### 变体 A：接手的已有代码（不是从零）

把第 2 步换成：

```
2. 这个目录已有代码但还没有 git。先阅读目录结构，报告技术栈、入口文件、如何运行；
   然后 git init -b main，并在 .gitignore 里补上本项目特有的产物目录。
```

### 变体 B：Node / TypeScript 项目

项目类型那行改成：

```
项目类型：Node.js + TypeScript，用 pnpm 管理依赖，构建产物到 dist/。
```

并在第 4 步后追加一句：

```
4.1 另外在 .npmrc 里设置 store-dir=.npmrc 同级的 .pnpm-store，避免依赖包被写到工作区外的盘根目录。
```

（原因见下面清单里的「pnpm 的 store 位置」。）

### 变体 C：Python 项目

```
项目类型：Python 3.13，用 venv 管理虚拟环境，源码在 src/。
```

`.gitignore` 要额外包含：`venv/`、`.venv/`、`__pycache__/`、`*.pyc`、`.pytest_cache/`、`*.egg-info/`。

## 二、开工前清单（按顺序过一遍）

| # | 事项 | 为什么 | 谁做 |
|---|---|---|---|
| 1 | **工作区路径用英文、不带空格** | PowerShell 5.1 按 ANSI 读脚本，中文/空格路径会被截断（这次在 `X项目1` 上踩过，脚本报错却不给日志） | 你 |
| 2 | 确认磁盘空间 | 依赖装起来动辄几百 MB，C 盘紧张就往 D/E 放 | 你 |
| 3 | 环境版本确认（git / node / pnpm / python） | 版本不匹配是后期最烦的坑，开工前一次看清 | 提示词第 1 步 |
| 4 | **`.gitignore` 先于第一次提交** | `.env` 一旦进历史就永久留存，只能改密码或重写历史 | 提示词第 4 步 |
| 5 | 项目级 git 身份（`--local`） | 个人项目和公司项目要用不同邮箱，全局只能有一个 | 提示词第 3 步 |
| 6 | **`AGENTS.md`** | 写清技术栈与约定，之后每次开新会话 DSH 都能秒懂项目，不用你反复解释 | 提示词第 7 步 |
| 7 | `.gitattributes`（可选） | 统一换行符，避免 Windows 上整文件"全改了一遍"的假 diff | 建议加 |
| 8 | `.env.example` | 让别人（和未来的你）知道要配哪些变量，但不泄露值 | 提示词第 6 步 |
| 9 | GitHub 建**空**仓库（Private） | 不勾 README / .gitignore / license，否则首推被拒 | 你 |
| 10 | 首次授权（浏览器点 Authorize） | 面板推送会弹 GCM；授权一次，之后免密 | 面板操作时 |
| 11 | 分支策略定下来 | 最小可用：`main` 永远可运行，新功能开分支，做完合回去 | 你 |
| 12 | 提交习惯 | 一件事一个提交，信息写"做了什么"而不是"修改" | 你 |

### 两个平台相关的小坑（本机实测）

**pnpm 的 store 位置。** pnpm 12 默认把 store 建在**项目所在盘的根目录**（`E:\.pnpm-store`），而不是项目里。在工作区受限的情况下，这会直接失败。解决办法是在项目根放一个 `.npmrc`：

```
store-dir=.pnpm-store
```

**沙箱写权限。** 新建的工作区目录如果是从别处拷来的，可能会出现 `SetNamedSecurityInfoW failed (Win32 5): grantWrite(...)` 这类报错——意思是这个目录的 ACL 缺了"写所有者"权限，DSH 沙箱无法授权。处理方法：让我跑一次 ACL 修复（我有一个专门的诊断脚本），或者把目录用文件管理器新建（继承父目录权限即可）。

## 三、建议的初始目录结构

```
my-project/
├─ .gitignore
├─ .gitattributes
├─ .env.example
├─ AGENTS.md
├─ README.md
├─ .npmrc              （Node 项目才需要）
├─ src/                （源码）
├─ docs/               （笔记、讲义、设计稿）
└─ tests/              （测试）
```

纯前端小项目可以把 `src` 摊平（就像现在的待办清单：`index.html` + `css/` + `js/`），结构服从项目规模，不必为了"标准"套模板。

## 四、AGENTS.md 模板

```markdown
# 项目说明（给 AI 协作者）

## 这是什么
<一句话：项目解决什么问题、给谁用>

## 技术栈
- 语言/框架：<...>
- 包管理：<pnpm / npm>
- 运行方式：<例如：直接用浏览器打开 index.html>

## 目录约定
- `src/` 源码
- `docs/` 文档与讲义
- 测试放 `tests/`

## 代码风格
- <缩进、命名、注释语言>
- 不引入新依赖前先问我

## 禁止事项
- 不提交 `.env`、密钥、token
- 不擅自修改 `main` 的历史（不 force push）
- 不改动 `docs/` 下已经定稿的讲义
```

## 五、最短路径总结

```
[你]   新建英文路径的工作区 → 开 DSH 会话 → 粘贴提示词
[DSH]  init + .gitignore + README + AGENTS.md + 首个提交（不推送）
[你]   GitHub 建空库（不勾任何初始化选项）
[面板] 更多 → 远程 → 添加远程 → 暂存 → 提交 → 发布分支
[日常] 改代码 → 面板暂存/提交/推送
```
