# 第 1 课：用 DSH 开张一个小项目，并做第一次 Git 提交

> 这一课的目标：**你能独立说清楚"我在让 DSH 干什么"、"Git 在替我保存什么"。**
> 全程不需要你敲一行命令——命令都由 DSH 代劳，但你要看懂它在做什么。

---

## 一、先认识 DSH 的三块地方

DSH 是一个"会自己动手的编程助手"，界面分三块：

| 位置 | 是什么 | 你在这里做什么 |
| --- | --- | --- |
| 左边/主体：对话区 | 你和 DSH 说话的地方 | 提需求、看它汇报、点"允许" |
| 右侧栏：面板区 | 文件树、Git、任务等面板 | 看它改了哪些文件、点一下看历史 |
| 底部/弹窗：确认区 | 需要你点头的操作 | 同意它运行命令、写文件 |

**和 DSH 说话的三条心法**

1. **说结果，不说步骤。** 说"我要一个能记录待办的网页，数据关掉还在"，比说"给我写个 index.html" 更省事。
2. **让它自己验收。** 好指令里带一句"做完自己跑一遍确认没问题"，它就会自查，而不是把半成品丢给你。
3. **你是验收方。** 它说完成 ≠ 真的对。打开看一眼，不对就说"第 3 条点不动"，它会自己找原因。

---

## 二、这一课做出来的东西

一个**待办清单网页**，双击 `index.html` 就能用：

- 输入内容 → 回车 → 加一条
- 点圆圈或文字 → 勾选完成
- 鼠标移上去 → 右侧 × → 删除
- 顶部三个按钮 → 全部 / 未完成 / 已完成
- 关掉浏览器再打开 → 数据还在（存在浏览器本地）

文件长这样：

```
X项目1/
├── index.html      页面骨架（写了什么元素）
├── css/style.css   长相（颜色、间距、圆角）
├── js/app.js       行为（增删改、保存、筛选）
├── README.md       说明书
└── .gitignore      告诉 Git "这些东西别管"
```

## 三、Git 到底是什么（一句话版）

**Git = 游戏存档系统。**

- 你玩到某个满意的进度，按一次"存档" → 这就是 `commit`（提交）
- 每个存档都带时间、带说明（"初版：待办清单"）→ 以后能翻回去看
- 存坏了？可以读回任意一个旧存档 → 这就是 `git checkout`
- 存档只存在你电脑上；想多一台电脑、多一个人看到 → 传到 GitHub，这就是 `push`

**核心四步循环**（记住这个就够了）：

```
改文件  →  git add  →  git commit  →  （以后）git push
  ↓          ↓            ↓                  ↓
 干活     挑出要存的     拍一张快照        备份到云端
```

两个必懂的概念：

- **工作区**：你眼前真实的文件（E:\DSH\X项目1 里的东西）
- **仓库（.git 文件夹）**：存档柜。`git init` 就是在项目里建了这个柜子

所以：**没有 `.git` 文件夹 = 不是 Git 项目 = 没有存档。**

## 四、这一课实际执行的命令

```bash
git init -b main          # 建仓库，主分支叫 main
git add -A                # 把所有改动放进"待存档"区
git commit -m "..."       # 拍快照，附一句说明
```

三个"看状态"的常用命令，随时可以问 DSH 帮你看：

```bash
git status        # 现在有哪些改动没存档
git log --oneline # 历史存档列表
git diff          # 具体改了哪几行
```

## 五、在面板里"看见"Git

右侧栏有 Git 面板（dsh-ide-git 插件），它把上面这些命令变成可点的按钮：

- **更改 / 暂存**：相当于 `git add`
- **提交**：填说明 + 按提交
- **提交图 / 分支树**：看清每个存档的先后顺序

> 看不到 Git 标签页？把 DSH 整个关掉重开一次即可（插件已装好，只是界面没刷新）。

## 六、常见误解对照表

| 你以为 | 实际 |
| --- | --- |
| 保存文件 = 存档 | 不是。Ctrl+S 只改工作区，Git 完全不知道 |
| 提交一次就要很久 | 几毫秒，本地操作，不需要联网 |
| 提交了别人就能看到 | 不是。要 `push` 到 GitHub 才行 |
| 删了文件就没了 | 只要提交过，随时能从历史里捞回来 |
| 一个项目只能有一个仓库 | 一个文件夹一个仓库，`git init` 只做一次 |

## 七、本课作业（2 分钟）

1. 双击 `index.html`，加 2 条待办，勾掉 1 条，刷新页面看数据是否还在。
2. 对 DSH 说：**"用 git status 看看现在有没有未提交的改动，并用大白话解释输出。"**
3. 再问它：**"git log 里那条提交，具体改了哪几个文件？"**

做完这三步，你就完成了从"用工具"到"管代码"的第一次跨越。
