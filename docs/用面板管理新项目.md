# 用 dsh-ide-git 面板管理新项目

## 先说清楚分工：面板管日常，两件事它不干

我翻了插件（0.23.0）的源码，它的动作表里有 `clone`、`remoteAdd`、`push`、`pull`、`stage`、`commit`、`branchCreate`、`stash`、`revert`、`reset`…… **但没有任何 `init`**，界面里也搜不到"初始化"三个字。

所以划一条线：

| 要做的事 | 面板能做吗 | 怎么办 |
|---|---|---|
| `git init`（文件夹变仓库） | **不能** | 一次性敲命令，或者让我代劳 |
| 在 GitHub 建空仓库 | **不能** | 网页 github.com/new（或让我用 API 建） |
| 编写 `.gitignore` 文件 | **不能**（面板不是编辑器） | 让我写，或用 VS Code/记事本建 |
| 克隆已有仓库 | 能（更多 → 克隆...） | — |
| 添加远程 origin | 能（更多 → 远程 → 添加远程...） | — |
| 暂存 / 提交 / 推送 / 拉取 | 能（主界面就是干这个的） | — |
| 建分支 / 切分支 / 合并 | 能 | — |
| 撤销上次提交 / 贮藏 / 重置 | 能（更多 → 提交 / 存储） | — |

一句话：**仓库存在之前的事归命令行，仓库存在之后的事归面板。**

---

## 一次性准备（三步，只做一遍）

### 1. 初始化仓库

```bash
cd D:\work\my-project
git init -b main
```

`-b main` 让初始分支直接叫 main（省得以后再改名）。旧版 git 不支持 `-b` 的话用 `git init` + `git branch -M main`。

### 2. 写 `.gitignore`

复制这份存成项目根目录的 `.gitignore`：

```gitignore
node_modules/
dist/
build/
out/
.venv/
__pycache__/
.env
.env.*
*.pem
*.key
*.log
.DS_Store
Thumbs.db
.vscode/
.idea/
```

（也可以直接把项目路径发我，我按你的技术栈生成一份。）

### 3. 在 GitHub 建空仓库

打开 https://github.com/new，填名字，选 Private，**下面三个勾全部不勾**（README / .gitignore / license），点 Create。

---

## 之后全部在面板里做（4 步）

### 第 1 步：添加远程 origin

面板 → 动作条右边的 **`⋯ 更多`** → **远程** → **添加远程...**

在弹出的两个输入框里填：

- 远程名称：`origin`
- 远程 URL：`https://github.com/你的用户名/my-project.git`

### 第 2 步：暂存要提交的文件

面板上半部分「**变更**」区会列出所有未跟踪文件。点行尾的**勾选/暂存**按钮（或列表顶部的"全部暂存"）把它们移到「**已暂存**」组。

> 暂存前瞄一眼：`.env`、`node_modules`、大文件都**不能**出现在这里。`.gitignore` 写好就不会出现。

### 第 3 步：提交

下方**提交框**写一句说明，比如 `初版：项目骨架`，按 **Ctrl+Enter**。

这是仓库的第一个提交。

### 第 4 步：推送（首次要"发布分支"）

点动作条的**推送**按钮。如果提示没有上游分支，改用：

**`⋯ 更多` → 远程 → 发布分支...**（选 origin）

它等价于 `git push -u origin main`，把本地 main 和 origin/main 绑上。**之后就直点推送按钮即可。**

---

## 认证：第一次推送会弹浏览器

面板里的 git 是**正常权限**运行的，所以它能调用 Git 凭据管理器（GCM）：

1. 点推送 → 弹出黑窗口或浏览器
2. 浏览器里点 **Authorize**（授权给 Git Credential Manager）
3. 回到面板，推送自动继续

授权一次，Windows 凭据管理器会记住 token，以后不再问。

> 对比：我这条 AI 命令跑在 Low IL 沙箱里，Schannel 拿不到凭据、`sh.exe` 也起不来，所以**我推送必须把 token 塞进 URL**。你点按钮不受这个限制——这就是面板推送比我手动推更省事的根本原因。

## 常见卡点

| 现象 | 原因 | 解法 |
|---|---|---|
| 面板里看不到"变更"，仓库像是空的 | 文件夹还没 `git init` | 一次性敲 `git init -b main`，面板刷新 |
| 推送报 `no upstream branch` | 本地分支没绑定远端 | 更多 → 远程 → 发布分支... |
| 推送报 `! [rejected] (fetch first)` | 建仓库时勾了 README，远端已有提交 | 动作条「拉取」→ 再推送 |
| 推送报 `Repository not found` | 仓库名/用户名拼错，或 token 没权限 | 核对 URL；删掉远程重加 |
| 变更列表里出现了 `.env` | `.gitignore` 没写或写错了 | 先 `git restore` 撤回暂存，补 `.gitignore` |
| 点提交没反应 | 提交框是空的，或没有暂存任何文件 | 先暂存，再写信息 |

## 一图流总结

```
[命令行] git init -b main          ← 只这一次
[编辑器] 写 .gitignore             ← 只这一次
[网页]   github.com/new 建空库     ← 只这一次
        ↓
[面板]   更多 → 远程 → 添加远程    ← 只这一次
[面板]   暂存 → 提交 → 发布分支    ← 只这一次
        ↓
[面板]   改代码 → 看变更 → 暂存 → 提交 → 推送   ← 以后每天
```
