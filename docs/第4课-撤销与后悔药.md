# 第 4 课：撤销与后悔药

这一课只解决一个问题：**改错了，怎么退回去。**

git 让人害怕的地方在于"回退"有一堆命令，用错一个就可能丢代码。其实只要先问自己一个问题，答案就唯一了：

> **这个改动，提交了吗？推送了吗？**

---

## 一、一张表定乾坤

| 你的处境 | 用什么 | 会不会改历史 |
|---|---|---|
| 改了文件，**还没提交** | `git restore 文件名` | 不动历史 |
| 提交了，**还没推送**，只想撤掉提交 | `git reset --soft HEAD~1` | 改本地历史 |
| 提交了，**还没推送**，改动也不要了 | `git reset --hard HEAD~1` | 改本地历史，内容一起没 |
| **已经推送**了，想撤销 | `git revert 提交号` | 不改历史，新增一条"反向提交" |
| 改到一半，要临时干别的 | `git stash` | 不动历史 |
| 上面全搞砸了，想找"消失的提交" | `git reflog` | 不动历史 |

记住这个顺序：**没提交 → 没推送 → 已推送**。越往后越要小心，因为改动已经"出门"了。

---

## 二、场景 A：改了，但还没提交

最常见。手滑删了一段代码、改乱了，还没存档。

```bash
git status              # 先看清哪个文件被改了
git diff README.md      # 看清改了什么
git restore README.md   # 一键还原成上次提交的样子
```

实测（本课真实输出）：

```
--- 现在有哪些改动 ---
 M README.md
--- 后悔：丢掉这一行 ---
--- 再看 ---
（干净 = 没有输出）
```

要点：
- `git restore` 丢掉的改动**找不回来**（它从没进过 git 仓库），所以先 `git diff` 看一眼再动手。
- 想一次性丢掉所有改动：`git restore .`
- 只想丢掉某个文件：后面写文件名。

**面板里的对应按钮**：变更列表里每个文件行尾的「丢弃」（垃圾桶图标）就是 `git restore`。它只丢这一个文件的改动，比命令行更安全，因为它只作用于你点的那一行。

## 三、场景 B：提交了，但还没推送

存档存错了地方，想退回上一步重来。

### 三种力度

```bash
git reset --soft  HEAD~1   # 撤掉提交，改动原样留在"暂存区"
git reset         HEAD~1   # 撤掉提交和暂存，改动还在文件里
git reset --hard  HEAD~1   # 撤掉提交、暂存、改动，全没了
```

`HEAD~1` 的意思是"往回退 1 个提交"，`HEAD~3` 就是退 3 个。

实测（本课真实输出）：

```
--- 后悔方式1：--soft（撤掉提交，改动留在暂存区）---
M  README.md
--- 现在反悔了，想连暂存也撤掉 ---
 M README.md
--- 最后把内容也丢掉 ---
（干净）
--- 历史回到原样 ---
b9aa031 chore: 忽略误落的凭据副本文件
58ba609 改标题：加上第 3 课
```

注意 `M` 前面有没有空格——有空格是在"更改"（没暂存），没空格是在"已暂存"。

### 只想改提交信息，不想改内容

```bash
git commit --amend -m "新的提交信息"
```

它会**替换**最后一条提交（包括提交信息），历史里还是只有一条。

**面板里的对应按钮**：提交框旁边的 amend 开关就是干这个的。

## 四、场景 C：已经推送到 GitHub 了

这时候**不要用 `reset --hard` + 强制推送**。原因：别人的仓库、你别的电脑、GitHub 上的记录都会和你对不上，而且容易把别人的提交冲掉。

正确做法是 `revert`——它不删历史，而是**新增一条"反向提交"**，把那次改动抵消掉：

```bash
git revert --no-edit 提交号
```

实测（本课真实输出）：

```
[practice-undo 98d8231] Revert "误加了一节内容"
--- 历史（多了一条还原记录）---
98d8231 Revert "误加了一节内容"
e7f5581 误加了一节内容
b9aa031 chore: 忽略误落的凭据副本文件
--- README 里那节内容还在吗 ---
False
```

历史里那条"误加"还在，但内容已经被抵消。这正是它的优点：**所有发生过的事都留了底**，谁什么时候撤的、撤了什么都查得到。

推上去之后，别人 `git pull` 就能同步到这次撤销，不需要任何强制操作。

## 五、场景 D：reflog —— 真正的后悔药

如果你已经 `reset --hard` 把提交弄没了，别慌。git 会在本地留一份"操作流水账"（reflog），默认保留 90 天：

```bash
git reflog              # 看最近的操作记录
git reset --hard 提交号  # 按记录把它救回来
```

实测（本课真实输出）：

```
--- 手滑执行 reset --hard 回退两条 ---
HEAD is now at e7f5581 误加了一节内容
--- 现在历史里还有它吗 ---
e7f5581 误加了一节内容
b9aa031 chore: 忽略误落的凭据副本文件
（没有了）
--- 后悔药：git reflog ---
e7f5581 HEAD@{0}: reset: moving to HEAD~2
38dda2d HEAD@{1}: commit: 重要改动
98d8231 HEAD@{2}: revert: Revert "误加了一节内容"
e7f5581 HEAD@{3}: commit: 误加了一节内容
b9aa031 HEAD@{4}: reset: moving to HEAD
--- 按记录把它救回来 ---
HEAD is now at 38dda2d 重要改动
38dda2d 重要改动
98d8231 Revert "误加了一节内容"
--- 内容回来了吗 ---
True
```

`HEAD@{1}: commit: 重要改动` —— 那行就是被"弄丢"的提交。**只要有 reflog，本地几乎什么都能救。**

补充两个查看旧版本的命令：

```bash
git show 38dda2d              # 看某个提交改了什么
git show 38dda2d:README.md    # 看那个提交里的 README 长什么样
git restore --source=38dda2d README.md   # 把旧版本的某个文件拿回来
```

## 六、场景 E：改到一半，要临时走开

活儿写到一半（半成品，不能提交），但你要切分支、拉代码、或者给别人看干净的工作区。

```bash
git stash push -u -m "写到一半的活儿"   # 收进抽屉（-u 连新文件一起收）
git stash list                         # 看看抽屉里有什么
git stash pop                          # 取出来，继续干
```

实测（本课真实输出）：

```
--- 当前有改动 ---
 M README.md
?? 新文件.txt
--- 先收进抽屉 ---
Saved working directory and index state On practice-undo: 写到一半的活儿
--- 工作区干净了 ---
（干净）
--- 抽屉里有什么 ---
stash@{0}: On practice-undo: 写到一半的活儿
--- 回来继续，取出来 ---
--- 改动回来了 ---
 M README.md
?? 新文件.txt
```

`stash` 不会产生提交，也不改历史，是"临时打包"。

---

## 七、三条铁律

1. **没推送之前，随便折腾。** 最坏情况有 reflog 兜底。
2. **推送之后，用 `revert`，不要 `push --force`。** force push 是唯一能把别人的活儿冲掉的操作。只有一种情况可以考虑：这个仓库只有你一个人，且你确定刚才那条提交没有任何价值。
3. **动手前先看两眼：`git status` 和 `git log --oneline -5`。** 知道自己在哪个分支、最近改了什么，90% 的误操作就能避免。

## 八、五分钟自测

在项目目录里依次做，最后回到干净状态：

```bash
git status                          # 应该是干净的
echo "测试" >> README.md            # 制造一个改动
git diff README.md                  # 看它
git restore README.md               # 丢掉它 → status 又干净
git status

git switch -c 练习-后悔药            # 建个练习分支，随便折腾
echo "练习" >> README.md
git add README.md
git commit -m "练习提交"
git revert --no-edit HEAD           # 体验反向提交
git log --oneline -3                # 看看历史长什么样
git switch main
git branch -D 练习-后悔药            # 删掉练习分支
```

做完对照一下：每个命令之后 `git status` 和 `git log` 分别变成什么样，你就把这一课学会了。

## 附：面板能做什么，不能做什么

`dsh-ide-git` 面板提供的是最常用的几个动作，对应关系如下：

| 面板上的操作 | 等价的命令 |
|---|---|
| 丢弃（变更行行尾） | `git restore 文件名` |
| 暂存 / 取消暂存 | `git add` / `git reset` |
| amend 开关 + 提交 | `git commit --amend` |
| 历史里点提交看详情 | `git show 提交号` |
| 推送 / 拉取 / 抓取 | `git push` / `git pull` / `git fetch` |

**面板没有**：`revert`、`reset`、`stash`、`reflog`。这几个需要敲命令，或者直接跟我说"帮我把上一条提交撤了"，我来执行并告诉你每一步发生了什么。
